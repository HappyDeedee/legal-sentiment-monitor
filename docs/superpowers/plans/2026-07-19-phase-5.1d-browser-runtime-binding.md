# Phase 5.1D Browser Runtime Binding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Use
> superpowers:test-driven-development for every production-code step. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make one account-bound BrowserEnvironmentProvider plan the only
browser, Profile, proxy, and identity authority for managed login checks and
crawl launches, then prove and persist customer-safe effective runtime values.

**Architecture:** Add a shared pure provider contract under `tools/` and a
monitor-side resolver under `api/monitoring/`. The monitor resolves the
persisted account identity once; direct Playwright callers consume the plan in
process, while Runner serializes the same internal plan to the MediaCrawler
child and reads back only a safe result. Existing Playwright/CDP remains the V1
provider. Managed identities fail closed instead of using generic Profiles,
process defaults, connect-existing CDP, dynamic proxies, or standard-browser
fallback.

**Tech Stack:** Python 3.11, frozen dataclasses, Playwright 1.45.0, Chromium
CDP, SQLite, FastAPI, existing static monitor UI, pytest.

## Confirmed Implementation Decisions

1. **Two layers, one authority.** `tools/browser_environment.py` contains the
   pure immutable plan/result contract, Playwright option/probe logic, child
   handoff, and safe-result validation. The monitor-side
   `api/monitoring/browser_environment_provider.py` reads database account and
   proxy records, validates them, derives the Profile, resolves the browser,
   creates the shared plan, and persists a validated safe result. Neither
   routes nor platform cores resolve individual fields again.
2. **Executable precedence.** A non-empty `MONITOR_BROWSER_EXECUTABLE` is
   authoritative and invalid input returns
   `account_identity_provider_unsupported` without fallback. When it is empty,
   formal managed paths use `playwright.chromium.executable_path` and record
   source `playwright_bundled`. `BrowserLauncher.detect_browser_paths()` stays
   only for legacy or explicitly diagnostic local flows.
3. **Profile authority.** Managed plans always derive `profile_path` from
   `profile_key` through `account_profile_environment()`. Stored legacy
   `profile_path`, platform-generic directories, and E14 fallback are never
   managed launch inputs. Cookie validation resolves the same account and
   `profile_key` but uses `profile_mode=ephemeral_cookie_validation`; CR-112
   remains owner of durable Cookie-to-Profile promotion.
4. **Proxy semantics.** A non-null account `proxy_id` means
   `policy=account_bound`; the exact active proxy is passed to browser and HTTP
   client adapters, and its browser-routed region proof must pass. A null
   account `proxy_id` means an explicit `policy=direct` with
   `effect_proof=not_applicable`; for a locked identity this is an explicit
   direct-network decision, not task-proxy or default-network fallback. This
   locked interpretation is recorded in `DECISIONS.md`, `GOAL.md`, and
   `ACCOUNT_ENVIRONMENT.md` without changing the existing pre-lock priority
   chain. A legacy account with no generated identity may keep that old chain.
   A task proxy that differs from a locked account proxy fails before launch
   with `account_identity_locked_proxy_override`.
5. **Proxy proof contract.** `MONITOR_BROWSER_PROXY_PROBE_URL` has no default.
   For an account-bound proxy, the provider opens a proof page immediately
   after context creation and completes proof before returning the context to
   any caller. It requires a JSON object whose `region` exactly equals the safe
   account `proxy_region_snapshot`. Platforms that navigate during login/pong
   therefore receive a pre-proved context. Missing URL, HTTP/navigation error,
   malformed response, or region mismatch fails closed. The probe uses its own
   timeout from `MONITOR_BROWSER_PROXY_PROBE_TIMEOUT_MS`, default `30000`,
   independent from QR/login/crawl timeouts. This is point-in-time proof; later
   proxy rotation or region drift requires another validation/reset rather than
   a per-request region claim. The URL, IP, response body, and proxy secret are
   not persisted or logged. Standard tests use fake pages and never contact a
   probe service.
6. **Required probes.** Effective evidence includes exact UA, timezone,
   `navigator.language`, normalized `navigator.languages`, captured
   `Accept-Language`, viewport, screen, device scale, touch points, mobile
   device class, provider mode, browser family/version/source, Profile key,
   proxy effect status, and `fallback_used=false`. `navigator.webdriver` is
   diagnostic only. Unsupported high-fidelity fields are listed as
   `not_managed` and never used as successful proof.
7. **CDP page preparation.** Launch-owned CDP uses the plan executable,
   derived Profile, proxy flag, and headless mode. Before each platform's first
   navigation, one awaited CDP preparation sequence applies
   `Emulation.setUserAgentOverride`, `Emulation.setTimezoneOverride`,
   `Emulation.setLocaleOverride`, `Emulation.setDeviceMetricsOverride`, and
   `Emulation.setTouchEmulationEnabled`, then marks that exact page prepared.
   Any missing/failed command rejects the page before navigation. The page is
   probed after navigation. A page created before preparation, managed
   connect-existing CDP, or managed CDP-to-standard fallback is a contract
   violation.
8. **Child handoff.** Runner places one internal serialized plan in
   `MONITOR_BROWSER_ENVIRONMENT_PLAN` and a safe result-file path in
   `MONITOR_BROWSER_ENVIRONMENT_RESULT_PATH`. The internal plan may contain the
   launch-only proxy secret and Profile path already required by the child; it
   is never written to logs, run summaries, database snapshots, or API output.
   UTF-8 serialized plan size is capped at `8192` bytes before spawn. The child
   parses and caches the immutable plan once, then removes the plan variable
   and managed HTTP(S)/ALL proxy variables from `os.environ` before any browser
   subprocess is launched; browser and HTTP adapters receive proxy values only
   from the cached plan. Logs may include only resolution ID, attempt ID,
   action, account ID, and safe source tags. The child result file is safe by
   construction and contains no secret/path.
9. **Persistence order.** Direct account validation and child crawl persist the
   validated safe result before reporting provider success. Mismatch/failure
   evidence may replace the prior runtime snapshot only after safe-shape and
   account/resolution checks. A missing, malformed, mismatched, or unsafe child
   result fails the managed crawl even when the child exit code is zero. Every
   child attempt receives a unique `attempt_id` and result path. The child
   writes `path.tmp.<pid>` and atomically replaces the result path only after
   validation; the parent deletes any destination before spawn and requires
   matching account, resolution ID, attempt ID, and fresh `validated_at`.
10. **Legacy boundary.** Only `identity_state=draft` with no generated identity
    may use the explicit legacy adapter and cannot claim Phase 5.1 fidelity.
    `generated`, `validated`, and `login_in_progress` require a managed plan
    and fail closed if validation/launch fails. `locked` and `active` require a
    managed plan for every check/crawl. `requires_relogin` is rejected with
    `account_identity_requires_relogin`; `resetting` retains the existing
    `account_identity_login_conflict`. Neither state can launch or fall back.
11. **Test boundary.** Standard pytest never launches a real browser, opens a
    real Profile, reaches a real proxy/probe/platform, or spawns a managed
    MediaCrawler child. Existing explicit real-side-effect flags remain the
    only opt-in; tests otherwise use fake Playwright/CDP objects and result
    files under pytest temporary roots.
12. **Failure and restart boundary.** A browser/context disconnect after proof
    fails the attempt with `account_identity_provider_browser_crashed`; it does
    not select another browser or mode. Existing account/run locks are acquired
    before provider resolution and held through result persistence/finalization.
    Existing startup stale-lock recovery remains authoritative after service
    restart; no new run reuses an in-memory plan or result from a terminated
    process.

## Provider Contract

The shared module exposes the frozen dataclasses below:

```python
@dataclass(frozen=True)
class BrowserEnvironmentPlan:
    contract_version: int
    resolution_id: str
    attempt_id: str
    action: str
    trigger_source: str
    workspace_id: int
    account_id: int
    platform: str
    identity_state: str
    identity_template: str
    browser_executable_path: str
    browser_family: str
    browser_source: str
    browser_version: str
    profile_key: str
    profile_path: str
    profile_mode: str
    proxy_policy: str
    proxy_id: int | None
    proxy_region: str
    proxy_url: str
    browser_platform: str
    user_agent: str
    timezone: str
    locale: str
    accept_language: str
    screen_width: int
    screen_height: int
    viewport_width: int
    viewport_height: int
    device_scale_factor: float
    is_mobile: bool
    has_touch: bool
    provider_name: str
    launch_mode: str
    headless: bool

@dataclass(frozen=True)
class BrowserEnvironmentResult:
    ok: bool
    reason: str
    snapshot: dict[str, Any]
```

The shared public function signatures are normative:

- `browser_context_options(plan: BrowserEnvironmentPlan) -> dict[str, Any]`
  returns exact Playwright launch/context inputs;
- `plan_from_environment(required: bool = False) -> BrowserEnvironmentPlan |
  None` consumes, validates, caches, and removes the one child plan from the
  process environment;
- `managed_proxy_formats() -> tuple[dict[str, Any] | None, str | None]`
  returns Playwright and HTTP client proxy values from that plan;
- `prepare_managed_page(context, page) -> None` applies required CDP overrides
  before first navigation;
- `verify_managed_page(context, page) -> BrowserEnvironmentResult | None`
  probes, compares, writes the safe result, and returns it;
- `write_browser_environment_result(result: BrowserEnvironmentResult) -> None`
  writes only the validated safe result path;
- `validate_safe_runtime_snapshot(snapshot: dict[str, Any]) -> dict[str, Any]`
  enforces the exact recursive allowlist.

The monitor resolver public signatures are normative:

- `resolve_account_browser_environment(account, *, action, trigger_source,
  headless, launch_mode, proxy=None, task_proxy_id=None,
  playwright_executable_path, diagnostic=False) -> BrowserEnvironmentPlan`;
- `persist_account_browser_environment_result(account_id, plan, result) ->
  dict[str, Any]`;
- `safe_browser_environment_summary(snapshot_json: str) -> dict[str, Any]`.

## Safe Snapshot Contract

Persisted/API-safe snapshot keys are bounded to:

```json
{
  "contract_version": 1,
  "resolution_id": "opaque",
  "attempt_id": "opaque",
  "action": "crawl",
  "trigger_source": "manual|scheduler|qrcode_login|cookie_validation|profile_validation",
  "account": {"workspace_id": 1, "account_id": 123, "platform": "dy", "identity_state": "active"},
  "browser": {"family": "chromium", "version": "126.0.6478.183", "source": "explicit|playwright_bundled"},
  "profile": {"profile_key": "1/dy/acc_123", "mode": "persistent"},
  "proxy": {"policy": "account_bound|direct", "proxy_id": 7, "region": "CN_MAINLAND", "effect_proof": "passed|not_applicable|failed"},
  "requested": {},
  "effective": {},
  "provider": {"name": "playwright", "mode": "persistent_launch|ephemeral_cookie_validation|cdp_launch", "version": "1.45.0"},
  "probes": {},
  "unsupported_fields": [],
  "mismatch_evidence": [],
  "fallback_used": false,
  "ok": true,
  "reason": "",
  "validated_at": "ISO-8601 UTC"
}
```

Forbidden recursively: Cookie values, proxy URLs/credentials, raw Profile or
executable paths, CDP/WebSocket URLs, debug ports, noVNC tokens, command lines,
environment dumps, fingerprint seed, probe URL, external IP, and raw exception
text.

## Acceptance Gate

Phase 5.1D passes when every managed QR/Profile/Cookie/crawl caller receives
one account-derived plan; all seven platform cores and CDP use it before first
navigation; effective values and proxy policy are proved or fail closed; safe
results are persisted without secrets/paths; managed fallbacks are impossible;
legacy and CR-112 boundaries remain intact; focused/full/docs/browser/review
gates pass; and the branch is merged and reverified.

This gate does not itself prove a real platform login/crawl, real account proxy
egress, container restart persistence, or production handoff. Those belong to
the next Phase 5.1 server-like acceptance packet.

## Stop Conditions

Stop and record the exact gap before implementation continues if:

- a formal managed caller requires a second browser/Profile/proxy authority;
- Playwright/CDP 1.45.0 cannot apply or probe a required field before first
  navigation;
- Playwright 1.45.0 CDP cannot apply the required UA/language/timezone/locale/
  metrics/touch command sequence to each page before first navigation;
- browser-routed proxy region cannot be proved through the configured contract;
- a safe child result cannot be bound to its account and `resolution_id`;
- implementation would require CR-112 Profile promotion/raw-Cookie changes;
- standard tests need a real browser, Profile, proxy, probe, or platform.

Do not resolve a stop condition by enabling process defaults, generic Profiles,
default network, local auto-detection, connect-existing CDP, standard fallback,
raw crawler authority, or secret-bearing logs/snapshots.
