# Phase 5.1P Browser Provider Preflight Packet

> This is the only currently executable packet in the CookieBridge roadmap.
> It is owned by existing CR-047 and is strictly read-only.

**Goal:** Map every browser/login/crawl entrypoint and define the minimum
`BrowserEnvironmentProvider` contract that Phase 5.1A-D can implement without
guessing.

**Must not change:** code, schema, UI, runtime data, databases, Profiles,
Cookies, proxies, browser processes, crawler behavior, deployment, or CR-112
implementation status.

- `docs/TASKS.md` Phase 5.1P
- `docs/ACCOUNT_ENVIRONMENT.md`
- `docs/SERVER_DEPLOYMENT.md`

## Tasks

- [ ] Confirm the current-main/worktree baseline and classify overlapping open
      tasks as current, gated, future-only, deferred, or historical.
- [ ] Create `docs/phase-5.1p-browser-entrypoint-map.md` with one row per QR
      login, visible browser login, Cookie validation, Profile login-state
      check, manual run, scheduler run, runner launch, CDP launch, and CDP
      reconnect path.
- [ ] For every row record caller, executable source, Profile source, proxy
      source, user-agent/locale/timezone/viewport source, headless mode,
      Playwright/CDP ownership, fallback behavior, validation, locks,
      finalization, and requested/effective evidence.
- [ ] Trace `MONITOR_BROWSER_EXECUTABLE` from configuration to actual consumers
      and record every path that bypasses it.
- [ ] Define an immutable provider result containing browser path/family/source,
      `profile_key`, derived Profile path, proxy, environment inputs, headless
      and provider mode, requested values, effective values, unsupported fields,
      mismatch evidence, and `fallback_used`.
- [ ] Classify each field as required/provable, supported/not-provable,
      unsupported, or diagnostic-only for the current Playwright/CDP provider.
- [ ] Prove whether one provider result can serve all mapped paths. Record any
      caller-specific adapter that is still required without creating a second
      authority.
- [ ] Define fail-closed behavior for invalid explicit executable, locked
      identity mismatch, unsupported required field, hidden task proxy override,
      process defaults, and default-network fallback.
- [ ] Keep local Chrome/Edge detection, visible login, and connect-existing CDP
      as diagnostic fallbacks; server-like execution remains acceptance proof.
- [ ] Obtain an independent read-only review of the complete map, callers, and
      missing evidence before Phase 5.1A starts.

## Exit Criteria

- The map has no unclassified entrypoint or hidden fallback.
- One provider contract covers login, validation, checks, runs, and CDP paths.
- Requested/effective snapshot fields and proof methods are explicit.
- Unsupported surfaces are named and are not silently claimed.
- Phase 5.1A-D can start without a browser/Profile/proxy authority decision.
- Project documentation checks and whitespace checks pass after the read-only
  evidence document is added.

## Stop Conditions

- A caller cannot consume the provider contract without changing accepted
  Phase 5.1 scope.
- A locked identity would still depend on process defaults or hidden fallback.
- Server-like proof cannot observe a required effective value.
- Current docs and code disagree on the authority for a field and the existing
  decision precedence does not resolve it.

When stopped, record the ambiguity as `Needs Confirmation`; do not start
Phase 5.1A-D or any CookieBridge packet.
