**Goal:** Add the accepted CR-047 account-identity fields and indexes to
`social_accounts` without guessing identity values, moving Profiles, or
changing login/crawl behavior.

**Architecture:** Extend the fresh SQLite table definition and add one
idempotent Phase 5.1A schema helper for existing databases. Existing rows gain
only documented safe defaults: empty nullable/configuration fields,
`identity_state='draft'`, and false integer flags. Existing account APIs remain
readable; boolean identity flags are normalized on read.

**Tech Stack:** Python 3.11, SQLite, pytest, existing
`api.monitoring.database` schema bootstrap.

```python
def _ensure_phase_51_account_identity_schema(conn: sqlite3.Connection) -> None:
    columns = (
        ("environment_region", "TEXT NOT NULL DEFAULT ''"),
        ("browser_platform", "TEXT NOT NULL DEFAULT ''"),
        ("identity_template", "TEXT NOT NULL DEFAULT ''"),
        ("fingerprint_seed", "TEXT NOT NULL DEFAULT ''"),
        ("user_agent", "TEXT NOT NULL DEFAULT ''"),
        ("timezone", "TEXT NOT NULL DEFAULT ''"),
        ("locale", "TEXT NOT NULL DEFAULT ''"),
        ("accept_language", "TEXT NOT NULL DEFAULT ''"),
        ("screen_width", "INTEGER"),
        ("screen_height", "INTEGER"),
        ("viewport_width", "INTEGER"),
        ("viewport_height", "INTEGER"),
        ("device_scale_factor", "REAL"),
        ("is_mobile", "INTEGER NOT NULL DEFAULT 0"),
        ("has_touch", "INTEGER NOT NULL DEFAULT 0"),
        ("identity_generator_name", "TEXT NOT NULL DEFAULT ''"),
        ("identity_generator_version", "TEXT NOT NULL DEFAULT ''"),
        ("identity_environment_version", "TEXT NOT NULL DEFAULT ''"),
        ("proxy_region_snapshot", "TEXT NOT NULL DEFAULT ''"),
        ("browser_environment_locked_at", "TEXT"),
        ("browser_environment_lock_reason", "TEXT NOT NULL DEFAULT ''"),
        ("requires_relogin", "INTEGER NOT NULL DEFAULT 0"),
        ("identity_state", "TEXT NOT NULL DEFAULT 'draft'"),
        ("identity_runtime_snapshot_json", "TEXT NOT NULL DEFAULT ''"),
    )
    for column, definition in columns:
        _ensure_column(conn, "social_accounts", column, definition)
    conn.executescript(
        """
        CREATE INDEX IF NOT EXISTS idx_social_accounts_identity_state
            ON social_accounts(workspace_id, identity_state);
        CREATE INDEX IF NOT EXISTS idx_social_accounts_requires_relogin
            ON social_accounts(workspace_id, requires_relogin);
        CREATE INDEX IF NOT EXISTS idx_social_accounts_identity_template
            ON social_accounts(workspace_id, identity_template);
        """
    )
```

## Acceptance Criteria

- Fresh and existing databases contain all 24 accepted Phase 5.1A fields.
- Migration is idempotent and creates all three documented indexes.
- Each new index is non-unique and has the exact workspace-scoped column order
  documented by the packet.
- Existing rows retain business, Profile, proxy, Cookie, and timestamp data.
- No identity field is guessed or copied from process/browser defaults.
- Existing accounts read successfully with `identity_state='draft'` and false
  Python boolean flags; nullable dimension/scale fields remain `None` when
  unset.
- Detail and list account reads continue to hide raw Profile filesystem paths.
- No Phase 5.1B-D, CR-070, CR-094, or CR-112 behavior is introduced.
- Focused tests, full monitoring tests, docs checks, syntax, whitespace, and
  independent review pass.

## Rollback And Recovery

Before deployment, revert the atomic Phase 5.1A commit. After a database has
opened the additive migration, code rollback remains readable because SQLite
ignores unused columns and indexes; no destructive down-migration is required.
The migration writes no identity values and moves no Profile data.

## Stop Conditions

Stop and record the ambiguity if implementation requires guessed legacy
identity values, destructive schema changes, Profile relocation, a new API
writer, identity generation/validation, state transitions, browser/provider
runtime behavior, or any CR-112 field. Stop if the existing database shape
lacks `workspace_id` or if a required index cannot be added without changing
current account semantics.
